SENGLED ELEMENT HUB RECLAIM 0.2-rc4
===================================

This release candidate incorporates the fixes proven during the first complete
Windows reclaim run on physical hardware.

Highlights
----------
* The normal installer preserves an already-working EZSP v7 coordinator and
  uses a single `RECLAIM` confirmation. The advanced `-ForceCoordinator` debug
  switch deliberately programs the public EZSP v7 image again and requires
  `FORCE-COORDINATOR`; it does not restore Sengled's original firmware.
* Coordinator flashing waits for legacy EBL finalization before reset and uses
  an ASH reset handshake during the live EZSP v7 verification.
* The Windows SquashFS process no longer extracts Linux device nodes onto NTFS.
  It uses a metadata-preserving tar conversion and accepts the validated stock
  rcS variant found on the tested hub.
* Long build and flash operations display explicit WAIT messages while their
  detailed output is buffered or written to logs.
* If the verified Bank2 image remains inactive after a warm reboot, the normal
  installer guides the required one-time cold power-cycle and resumes its
  health check. No second backup, build, or flash is needed.
* Bank2 health detection works with the stock BusyBox feature set and verifies
  TCP/6638 from the Windows PC.
* TEST-BANK2-BOOT.cmd provides a non-destructive standalone health check.
* Package checksums exclude runtime downloads, making the release manifest
  stable and independently verifiable.
* Original project code and documentation are distributed under the MIT
  License; downloaded third-party components retain their upstream licenses.

Start here
----------
Extract the whole ZIP, read README-FIRST.txt, and double-click
RECLAIM-SENGLED-HUB.cmd. Keep both the hub and PC powered during every stage
marked WAIT. Bank1 is never written by this tool.
